# 서류작성 도우미 v2 설계

기준일: 2026-11-09

## 1. 의도

현재 MVP의 사진 기반 작성칸 안내를 경진대회 출품 가능한 새 버전으로 확장한다. 새 버전은 세 가지 문제를 순서대로 해결한다.

1. 체크박스, 날짜, 서명처럼 현재 오인식이 많은 작성 단위를 더 정확히 찾는다.
2. 서식에 인쇄된 행정규칙명, 서식번호, 발령번호, 소관기관을 단서로 국가법령정보센터 정본을 역조회하고 관련 법률-시행령-시행규칙과 실제 민원 절차를 근거와 함께 보여준다.
3. 한국어를 기준 원문으로 유지하면서 영어, 일본어, 중국어 간체, 필리핀어, 베트남어 안내를 제공한다.

서비스는 서류를 대신 작성하거나 법률 판단을 내리는 제품이 아니다. 사용자가 종이 서류를 이해하고 직접 작성하도록 돕는 것이 목적이다.

## 2. 확정된 사용자 요구

- 지원 언어: 한국어, 영어, 일본어, 중국어 간체, 필리핀어, 베트남어
- 법령 데이터의 기준: 국가법령정보센터 Open API
- OpenAI의 역할: 이미지 판독 보강, 쉬운 요약, 근거 제한 절차 설명, 번역
- 법령 연결: 서식에서 행정규칙명 등을 추출한 뒤 정본을 역조회하고 가능한 경우 법률-시행령-시행규칙 3단 관계를 제공
- 절차 안내: 법령 조문과 별표뿐 아니라 소관기관 공식 안내를 근거로 접수처, 제출 방법, 준비물, 수수료, 처리기간, 문의처를 구분해 제시

## 3. 목표와 성공 기준

### 3.1 인식 정확도

- 체크박스, 날짜, 서명/날인 후보를 일반 텍스트 필드와 분리해 재검증한다.
- 기존 134개 작성 단위 기준표에서 기존 통과 항목을 후퇴시키지 않는다.
- 체크박스, 날짜, 서명/날인 오류 항목은 변경 전후 결과를 별도로 기록한다.
- 불확실한 결과는 잘못된 확정보다 `확인 필요` 또는 수동 영역 수정으로 보낸다.
- v2 완료 게이트는 134개 기준표의 `누락+오매핑` 13건을 3건 이하로 줄이고, 기존 통과 86건을 모두 유지하는 것이다.
- 체크박스, 날짜, 서명/날인은 범주별 평가 표본을 최소 10개로 보강하고 각각 정밀도 95% 이상, 재현율 90% 이상을 목표로 한다. 표본이 부족하면 수치를 일반화하지 않고 실제 표본 수와 결과를 함께 제출한다.
- 서명/날인을 다른 사람이나 다른 작성칸에 확정 배정하는 오류는 허용하지 않으며, 모호하면 반드시 `확인 필요`로 보낸다.

### 3.2 법령과 절차

- 모델이 생성한 법령명이나 조문을 정본처럼 표시하지 않는다.
- 화면에 표시되는 법령, 행정규칙, 조문, 시행일, 소관부처는 국가법령정보센터 응답으로 확인된 값이어야 한다.
- 동명 후보가 여러 개면 소관기관, 발령번호, 서식번호, 현행 여부로 판별하고 확정하지 못하면 사용자에게 후보를 보여준다.
- 모호한 후보는 v2 화면에서 사용자가 직접 선택할 수 있다. 선택 시 법령 상세를 다시 조회하고 법령 요약·절차·번역 캐시를 새 선택 기준으로 갱신한다.
- 모든 법적 근거와 절차 항목은 출처 ID를 가진다.
- 절차 정보에 공식 근거가 없으면 해당 항목을 비우거나 `공식 안내를 확인하지 못했어요`로 표시한다.

### 3.3 다국어

- 정적 UI는 로컬 사전으로 즉시 전환한다.
- 동적 AI 안내는 검증된 한국어 기준 데이터를 번역한다.
- 번역 화면에도 한국어 법령명, 조문번호, 기관명, 시행일, 공식 링크를 유지한다.
- 번역 실패 시 한국어 원문으로 안전하게 되돌아간다.
- 법적 효력은 한국어 공식 원문에 있음을 항상 표시한다.

## 4. 비목표

- 서류 자동 작성, 전자서명, 민원 자동 제출
- 개인별 법률 자문이나 자격 판정
- 모든 행정규칙을 억지로 법률-시행령-시행규칙 구조에 연결
- 출처 없는 수수료, 처리기간, 준비물 생성
- 전체 사이트를 번역 모델에 맡겨 매 요청마다 자유 번역
- 초기 버전에서 사용자 계정, 영구 저장, 다중 서버 공유 세션 구현

## 5. 고려한 접근

### 접근 A: OpenAI 중심 검색과 관계 구성

모델이 서식에서 법령명을 읽고 웹 검색으로 관련 법령과 절차를 구성한다. 구현은 빠르지만 동명 규칙, 폐지 규칙, 구판, 상하위법 관계를 잘못 연결할 위험이 커서 채택하지 않는다.

### 접근 B: 국가법령정보 API 중심

모델은 인쇄된 검색 단서만 추출하고, 정본 식별과 상하위법 연결은 국가법령정보센터 API로 확정한다. OpenAI는 정본 데이터의 쉬운 요약과 번역만 담당한다. 정확성과 설명 가능성이 가장 높다.

### 접근 C: 사전 구축한 민원서식 카탈로그 중심

대회 시연용 서식을 수동 등록해 빠르고 안정적으로 안내한다. 범용 서류 인식이라는 제품 강점이 약해지고 새 서식 대응이 제한된다.

### 선택

접근 B를 기본으로 채택한다. 다만 API 응답 캐시는 운영 안정성을 위한 기술 요소로 사용한다. 캐시는 정본을 대체하지 않으며 조회 시각과 데이터 버전을 함께 보존한다.

## 6. 전체 사용자 흐름

1. 사용자가 사진을 올린다.
2. 클라이언트가 해상도, 흐림, 방향, 가장자리 잘림을 점검한다.
3. OpenAI 비전 분석이 서류 제목, 기관, 서식번호, 개정일, 행정규칙명/근거 문구와 작성칸을 구조화한다.
4. 서버가 체크박스, 날짜, 서명/날인 후보를 별도 이미지 영역으로 재검증한다.
5. 작성 가능한 첫 칸부터 기존처럼 점진적으로 표시한다.
6. 법령 단서가 있으면 국가법령정보센터 API에서 행정규칙 또는 법령 정본 후보를 조회한다.
7. 후보를 확정한 뒤 체계도, 위임법령, 3단 비교, 본문/별표를 조회한다.
8. 공식 기관 검색으로 실제 민원 절차 자료를 찾고 정본과 기관 일치 여부를 검증한다.
9. OpenAI가 확인된 근거만 사용해 쉬운 한국어 법령·절차 안내를 생성한다.
10. 사용자가 언어를 바꾸면 정적 UI는 즉시 바뀌고 동적 안내는 기준 한국어 결과를 번역해 표시한다.
11. 사용자는 작성칸 안내와 별도의 `법령·절차` 화면에서 근거, 소관기관, 진행 순서를 확인한다.

## 7. 인식 정확도 설계

### 7.1 사진 품질 점검

- 기존 `normalizeImage` 결과에 밝기, 선명도, 문서 가장자리 가시성, 회전 경고를 추가한다.
- 분석을 막는 오류와 계속 진행 가능한 경고를 구분한다.
- 개인정보 가림 안내는 유지한다.

### 7.2 특수 작성 단위

일반 필드 분석 결과에 `kind`를 추가한다.

- `text`
- `checkbox_group`
- `date`
- `signature`
- `stamp`
- `number`
- `unknown`

첫 판독 뒤 체크박스, 날짜, 서명/날인 후보 영역을 확대 재판독한다. 재판독은 다음을 반환한다.

- 실제 작성 영역 좌표
- 인쇄 라벨과 작성 주체
- 선택지 또는 날짜 구성요소
- 신청인 작성란인지 직원 작성란인지
- 확신도와 확인 필요 사유

모델 결과는 기존 표선/셀 검출, 좌표 경계, 중복 제거 규칙을 통과해야 저장한다.

### 7.3 진행 상태

- 확인한 필드 ID를 현재 세션에 유지한다.
- 전체 분석 완료 전에는 진행률을 확정 비율로 표시하지 않는다.
- 완료 화면에는 `확인한 칸`, `아직 확인하지 않은 칸`, `수동 확인이 필요한 칸`을 구분한다.

## 8. 국가법령정보센터 연동

### 8.1 인증과 설정

- 인증값은 `LAW_OPEN_API_OC` 서버 환경 변수에만 저장한다.
- 클라이언트 번들, API 응답, 로그, 오류 메시지에 인증값을 포함하지 않는다.
- 사용자가 대화에서 제공한 실제 값은 소스와 설계 문서에 기록하지 않는다.

### 8.2 추출할 법령 단서

`DocumentReading`에 다음 인쇄 메타데이터를 추가한다.

- 행정규칙명 또는 법령명
- 발령번호/공포번호
- 근거 조문 원문
- 별표/별지 서식 번호와 명칭
- 소관기관/발령기관
- 시행일/개정일 후보

기입된 개인정보는 법령 단서로 보내지 않는다.

### 8.3 조회 순서

1. 정확한 행정규칙명 또는 법령명으로 목록 조회
2. 소관기관, 번호, 날짜, 현행 여부로 후보 점수화
3. 유일한 확정 후보만 자동 선택
   - 여러 후보가 남으면 이름, 구분, 소관기관, 번호, 시행일, 현행 여부를 보여주고 사용자 선택을 기다린다.
4. 행정규칙/법령 본문 및 별표 조회
5. 위임법령 또는 인용법령 관계 조회
6. 법령 체계도 조회
7. 법률 정본을 기준으로 3단 비교 조회
8. 관련 조문과 별표 링크 저장

행정규칙은 훈령, 예규, 고시, 지침일 수 있으므로 시행규칙과 동일시하지 않는다. 체계도 또는 위임 관계가 확인된 경우에만 상위 법령을 연결한다. 3단 비교가 존재하지 않으면 존재하지 않는 것으로 명시한다.

### 8.4 데이터 모델

`LegalContext`는 다음을 가진다.

- `status`: `pending | completed | unavailable | ambiguous | not_found`
- `detectedReferences`: 사진에서 읽은 원문 단서
- `canonicalRule`: 확정된 행정규칙 또는 법령
- `hierarchy`: 법률, 시행령, 시행규칙, 관련 행정규칙
- `provisions`: 관련 조문, 제목, 시행일, 근거 유형
- `forms`: 별표/별지 서식 링크
- `authority`: 소관부처와 담당기관
- `procedure`: 접수처, 제출방법, 준비물, 수수료, 처리기간, 문의처
- `sources`: 국가법령정보센터 또는 공식 기관 URL과 조회 시각
- `warnings`: 판본 불일치, 후보 불명확, 공식 절차 미확인

### 8.5 API 클라이언트

- 별도 `lib/legal` 모듈에서 네트워크 호출, XML/JSON 정규화, 후보 판별, 캐시를 담당한다.
- 타임아웃과 최대 응답 크기를 제한한다.
- 외부 오류 본문을 사용자에게 노출하지 않는다.
- 정본 응답은 TTL 기반 LRU 메모리 캐시에 저장한다.
- 초기 TTL은 현행 법령 목록 6시간, 본문/체계도/3단 비교 24시간으로 두고 테스트 가능한 상수로 관리한다.
- 만료 응답은 즉시 삭제하지 않고 최대 7일간 stale 영역에 보존한다. 정상 조회에는 사용하지 않으며, 동일 요청의 외부 API 장애 때만 `마지막 확인 시각`과 `최신 정보가 아닐 수 있음` 경고를 붙여 표시한다.
- 서버 재시작 시 캐시가 사라지는 것은 v2 초기 범위에서 허용한다.

## 9. 절차 안내와 OpenAI 역할

절차 안내는 두 계층으로 분리한다.

1. `법적 근거`: 국가법령정보센터의 조문, 별표, 체계도, 시행일
2. `실제 처리 절차`: 소관기관 공식 홈페이지의 신청 안내, 온라인 민원 페이지, 공고

OpenAI 웹 검색은 중앙부처·지자체·정부24·국가법령정보센터·공공기관의 공식 도메인으로 제한하고, 검색된 URL을 서버가 다시 정책 검증한다. 기본 허용 범위는 `*.go.kr`, `gov.kr`, `*.gov.kr`, `law.go.kr`이며, 공공기관의 별도 도메인은 공식 정부 페이지에서 기관 링크가 확인된 경우에만 서버 allowlist에 추가한다. OpenAI에는 사진 전체나 개인정보를 검색 입력으로 보내지 않고 정본 법령명, 기관명, 서식번호만 보낸다.

검색 결과의 제목·요약만으로 절차를 확정하지 않는다. 서버가 허용된 URL의 공개 HTML을 직접 가져와 본문 근거를 추출하되, HTTPS만 허용하고 DNS/IP 재검증, 리다이렉트 제한, 사설 IP 차단, 응답 크기·시간 제한을 적용한다. PDF 등 비HTML 자료는 v2에서 링크와 공식 메타데이터만 제공하며 본문 자동 추출은 후속 범위로 둔다.

OpenAI 요약은 근거 ID를 필수로 반환하는 Structured Output을 사용한다. 근거 없는 절차 항목은 빈값으로 반환한다. 법률 효과, 자격, 대리권을 새로 판단하지 않는다.

## 10. 다국어 설계

### 10.1 언어 코드

- 한국어: `ko`
- 영어: `en`
- 일본어: `ja`
- 중국어 간체: `zh-CN`
- 필리핀어: `fil`
- 베트남어: `vi`

### 10.2 정적 UI

- 버튼, 제목, 오류, 개인정보 안내, 면책 문구는 코드 내 버전 관리되는 번역 사전을 사용한다.
- 초기 영어·일본어·중국어 간체·필리핀어·베트남어 사전 작성과 자동 구조 검사는 구현 범위에 포함한다. 원어민 또는 전문 번역가 검수가 완료되기 전에는 언어 선택기에 `베타`를 표시하고, 검수 상태를 언어별 메타데이터로 관리한다.
- 언어 선택은 첫 화면과 상단 헤더에서 가능하다.
- 선택 언어는 브라우저 저장소에 보관하되 개인정보나 분석 세션과 결합하지 않는다.

### 10.3 동적 안내 번역

- 먼저 한국어 기준 안내를 생성하고 검증한다.
- 번역 요청에는 기준 텍스트, 보존해야 할 고유명사, 숫자, 법령명, 조문번호, 출처 ID를 구조화해 전달한다.
- 번역 응답은 원문과 같은 키 구조를 유지한다.
- 법령명과 기관명은 한국어 원문을 함께 보존하고 괄호 안에 번역을 제공한다.
- 번역 캐시는 `analysisId + analysisVersion + language + contentHash`로 구분한다.
- 사용자가 언어를 바꿔도 사진 재분석이나 법령 API 재호출은 하지 않는다.

### 10.4 번역 검증

- 출처 ID, URL, 조문번호, 날짜, 금액이 원문과 같은지 서버가 검사한다.
- 번역 모델이 항목을 추가하거나 삭제하면 응답을 거부한다.
- 법률·절차 번역에는 `편의를 위한 번역이며 한국어 공식 원문을 확인하세요`를 표시한다.

## 11. 화면 설계

기존 모바일 우선 흐름을 유지한다.

- 헤더: 글자 크기, 도움말 옆에 언어 선택
- 사진 확인: 품질 점검 결과와 재촬영 사유
- 서류 확인: 제목, 기관, 서식번호와 함께 읽힌 행정규칙/법령 단서 표시
- 작성칸 화면: 기존 칸 안내와 진행 상태
- 법령·절차 진입점: 작성칸 화면 상단 또는 서류 제목 아래에 독립 버튼
- 법령·절차 화면:
  - 이 서식의 근거
  - 법률-시행령-시행규칙 연결
  - 관련 행정규칙
  - 신청 절차
  - 공식 출처와 조회일
  - 확인 필요 경고
- 완료 화면: 확인한 칸/남은 칸/수동 확인 필요 칸 및 법령·절차 다시 보기

법령·절차 정보가 아직 준비되지 않았어도 작성칸 안내를 막지 않는다.

## 12. API와 상태 흐름

분석 스트림에 법령 단계 이벤트를 추가한다.

- `legal_started`
- `legal_reference`
- `legal_complete`
- `legal_unavailable`

법령 조회는 작성칸 매핑이 시작된 뒤 법령 단서가 확보되면 병렬로 시작할 수 있다. 작성칸 스트림의 첫 결과를 지연시키지 않는다.

새 서버 API:

- `GET /api/documents/legal?analysisId=...`: 현재 법령·절차 상태 조회
- `POST /api/documents/translate`: 검증된 분석/법령/안내의 목표 언어 번역

기존 세션 버전이 바뀌면 관련 번역 캐시를 무효화한다.

## 13. 오류와 안전 동작

- 국가법령정보 API 미설정: 작성칸 안내는 계속하고 법령 기능에 설정 필요 표시
- 후보 없음: 검색 단서와 함께 `관련 정본을 확인하지 못했어요`
- 후보 다수: 자동 확정하지 않고 후보 선택 또는 기관 확인 안내
- API 장애: 마지막 캐시가 있으면 조회 시각과 함께 표시, 없으면 확인 불가
- 판본 불일치: 현행 정본을 기본으로 제공하되 사진에서 읽은 발령·개정·시행일과 다름을 명확히 경고한다. 사진 시점의 과거 정본을 API에서 유일하게 식별할 수 있으면 별도 링크와 메타데이터를 함께 제공하지만, v2에서는 과거·현행 조문 자동 비교를 하지 않는다.
- 번역 실패: 한국어 기준 안내 유지
- 공식 절차 없음: 법령 요약만 표시하고 절차를 생성하지 않음

## 14. 보안과 개인정보

- OpenAI API 키와 국가법령정보 API 인증값은 서버 환경 변수로만 관리한다.
- 분석 사진과 개인정보는 국가법령정보 API 또는 웹 검색으로 보내지 않는다.
- 번역에는 실제 기입값을 포함하지 않는다.
- 외부 API URL, 응답 크기, 리다이렉트, 콘텐츠 형식을 제한한다.
- 서버 로그에는 인증값, 사진 데이터 URL, 원문 개인정보를 남기지 않는다.
- 법령 및 절차는 참고 정보이며 최종 확인은 공식 원문과 접수기관 기준임을 표시한다.

## 15. 테스트와 검증

### 단위 테스트

- 법령 API URL 구성과 인증값 비노출
- XML/JSON 응답 정규화
- 동명 후보 판별 및 모호성 처리
- 사용자 후보 선택 후 상세 재조회와 파생 캐시 무효화
- 행정규칙과 시행규칙 구분
- 체계도/3단 비교 없음 처리
- 캐시 TTL과 장애 시 fallback
- 만료 후 7일 stale 보존, 정상 요청 미사용, 장애 시 경고 표시
- 절차 근거 ID 강제
- 다국어 구조 보존, 숫자/날짜/URL/조문번호 불변성
- 번역 실패 시 한국어 fallback
- 체크박스/날짜/서명 판독 결과 검증 및 중복 제거

### 통합 테스트

- 가상 국가법령정보 API 서버를 사용한 전체 법령 조회 흐름
- OpenAI 응답을 고정한 한국어 요약과 5개 번역 흐름
- 점진 분석과 법령 조회가 서로를 지연시키지 않는지 확인
- 세션 만료, 수동 영역 수정, 법령/번역 캐시 무효화 확인

### 수동 검수

- 기존 전기안전공사 서식으로 행정규칙 단서, 정본, 체계도, 절차 화면 확인
- 기존 3종 134개 작성 단위 결과와 전후 비교
- 각 언어에서 모바일 레이아웃, 줄바꿈, 법령 원문 병기, 출처 링크 확인
- 실제 API 인증값으로 호출하는 검증은 명시적 실행 옵션에서만 수행해 비용과 트래픽을 통제
- 언어별 번역 사전은 구현자 자체 검수 상태로 시작하며, 출품 전 가능한 범위에서 원어민 또는 전문 번역 검수를 별도 체크리스트로 수행

## 16. 구현 순서

1. 테스트 가능한 타입과 법령 API 클라이언트 기반

5. 법령·절차 화면

7. 동적 안내 번역과 검증

## 17. 구현자에게 맡기는 세부 결정

- 내부 모듈의 정확한 파일 분할과 함수명
- LRU 캐시 구현 방식
- 모바일 화면에서 법령 계층을 카드 또는 접이식 목록으로 표시하는 세부 스타일
- 테스트 fixture의 구체적인 문자열과 식별자

위 결정은 이 문서의 정확성, 출처, 개인정보, fallback 원칙을 바꾸지 않아야 한다.
