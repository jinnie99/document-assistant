# 서류 작성 도우미 — 고객 인수인계본

전달 기준일: 2026-10-29. 현재 개발 중인 MVP의 소스와 실행 설정을 정리한 패키지입니다.
서류 사진을 올리면 AI가 서류 이름과 용도를 먼저 확인하고, 작성할 칸을 순차적으로 찾습니다.
공식 서식·작성 안내를 검색하고, 근거가 부족한 경우 사진을 바탕으로 AI가 설명합니다.
각 칸을 누르면 작성 예시와 확인 내용을 함께 볼 수 있고, 영역 수정·칸 추가도 가능합니다.
메인 화면 위쪽의 국기를 누르면 화면과 AI 안내가 그 언어(한국어·English·中文·Tiếng Việt·日本語·ไทย)로 바뀝니다. 서식과 법령·근거 자료는 한국어 원문 그대로 보여 줍니다.

## 먼저 확인할 파일

- `docs/KNOWN_ISSUES.md`: 현재 기능 범위, 정확성 문제, 후속 개발 항목
- `docs/사용매뉴얼.pdf`: 전기안전공사 정기검사 신청서로 실제 테스트한 화면 안내
- `docs/사용매뉴얼.docx`: 수정 가능한 동일 매뉴얼
- `docs/samples/전기안전공사.png`: 매뉴얼에서 사용한 빈 서류 사진
- `docs/verification/`: 자동 테스트 결과와 기존 서류 전수 점검 결과
- `third-party/`: 함께 배포하는 글꼴 및 PDF.js의 라이선스

## 실행 환경

- Node.js **24.x**와 함께 제공되는 npm을 사용합니다. 전달 전 검사 환경은 Node.js 24.22.1 / Windows입니다.
- 인터넷 연결과 사용 가능한 OpenAI API 계정·모델 권한이 필요합니다.
- 별도 데이터베이스는 사용하지 않습니다. 현재 분석 세션은 서버 메모리에 저장됩니다.
- `node_modules`와 빌드 결과는 포함하지 않았습니다. 아래 순서로 설치·빌드합니다.

## 빠른 실행

ZIP 전체를 쓰기 가능한 로컬 폴더에 압축 해제하고, `package.json`이 있는 `document-assistant` 폴더에서 실행합니다.
Windows에서는 파일 탐색기의 숨김 파일 표시 여부와 관계없이 `.env.local`이 실제로 해제되었는지 확인해 주세요.

```powershell
node --version
npm ci
npm run build
npm run start -- --hostname 127.0.0.1 --port 3000
```

브라우저에서 http://127.0.0.1:3000/assist 를 엽니다. `/`도 이 화면으로 이동합니다.
3000번 포트가 이미 사용 중이면 마지막 명령의 포트를 3002 등으로 바꾸고 같은 포트로 접속합니다.

개발하면서 수정할 때:

```powershell
npm run dev -- --hostname 127.0.0.1 --port 3000
```

개발 서버와 운영 서버를 같은 작업 폴더에서 동시에 실행하지 마세요. 각각 별도 압축 해제본을 사용하면 됩니다.

## 환경 설정과 키

요청에 따라 원본 `.env.local`과 `.env.example`을 **내용 변경 없이 포함**했습니다.
`.env.local`에는 실제 키가 들어 있으므로 ZIP과 해제 폴더를 비공개로 보관하고 고객과 안전한 경로로 전달해 주세요.
키 값은 README·매뉴얼·검증 보고서에 복사하지 않았습니다.

- `OPENAI_API_KEY`: `/assist`의 서류 판독, 검색, 안내에 사용하는 서버 측 키
- `OPENAI_MODEL`: 사용할 모델. 현재 전달한 환경 파일 값을 그대로 사용합니다.
- `LAW_OPEN_API_OC`: 국가법령정보센터 Open API의 서버 측 인증값. 법령·행정규칙 정본 역조회에 사용하며 브라우저로 전달하지 않습니다.
- `.env.example`: 새 환경을 만들 때 참고하는 빈 설정 예시입니다. 기존 `.env.local`을 덮어쓰지 마세요.
- `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`: 보존된 구형 `/try` 흐름의 선택 설정이며, 주 서비스 `/assist` 실행에는 필요하지 않습니다. 없는 키를 새로 넣지는 않았습니다.

환경 파일을 수정하면 서버를 다시 시작합니다. 키가 거절되거나 호출 제한에 걸리면 OpenAI 계정의 키 상태·권한·한도를 확인합니다.
고객별 운영 환경에서는 고객 소유 키로 교체하는 방식으로 비용과 권한을 분리할 수 있습니다.

## 소스 구성

| 경로 | 내용 |
| --- | --- |
| `app/assist/` | 사진 업로드, 단계별 분석 상태, 서류 칸 선택·확대, 작성 안내 화면 |
| `app/api/documents/` | 분석 스트림, 칸별 안내, 세션·영역 수정 API |
| `lib/documents/` | OpenAI 연동, 검색·근거 처리, 표 셀 탐지, 좌표 계산, 검증·메모리 세션 |
| `lib/legal/` | 국가법령정보센터 API, 법령 후보 판별, 캐시, 법령·절차 근거 처리 |
| `components/`, `public/` | 공통 화면 요소, 정적 이미지·글꼴·PDF 작업자 파일 |
| `tests/documents/`, `tests/fixtures/` | 단위·회귀 테스트와 가상 서류 이미지 |
| `scripts/` | 포함 테스트에서 사용하는 전수 점검 검증 함수와 점진 분석 검증 도구 |
| `app/try/`, `app/legacy/`, 기존 API | 이전 실험 화면·기능. 주 서비스와 구분하여 참고 |

기존 소스 파일과 잠금 파일은 그대로 보존했습니다. 전달용 README와 인수인계 문서만 별도로 정리했습니다.
내부 개발 이력, `.git`, `.ai-docs`, 임시 로그·캡처, 개발자 PC 경로에 의존하는 진단·문서 생성 도구는 제외했습니다.
원본 전체 작성 칸 점검의 표와 요약은 참고 자료이며, 내부 원자료·모든 외부 테스트 서식은 이 패키지에 포함되지 않습니다.

## 코드 검사

```powershell
npm test
npx eslint app components lib scripts tests
npm run build
npx tsc --noEmit
```

TypeScript 검사는 Next.js의 자동 생성 타입을 사용하므로 먼저 빌드합니다.
현재 `npm run lint`는 전체 폴더를 검사하므로, 그대로 배포하는 PDF.js 작업자 파일까지 검사해 불필요한 결과가 나올 수 있습니다.
앱 소스 검사에는 위의 범위를 지정한 ESLint 명령을 사용합니다.

자동 테스트 통과는 AI가 모든 서류의 칸을 정확하게 인식한다는 뜻이 아닙니다.
남아 있는 문제와 검수 결과를 반드시 `docs/KNOWN_ISSUES.md`에서 함께 확인해 주세요.
