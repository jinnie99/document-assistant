# 서류작성 도우미

종이 서류 사진을 찍어 올리면 AI가 **작성할 칸을 찾아 표시**하고, 칸마다 **무엇을 적는지·작성 예시·다 쓴 뒤 확인할 내용**을 쉬운 말로 안내하는 웹 서비스입니다.
한국어가 서툰 외국인 주민, 서류가 낯선 어르신처럼 관공서 서류 앞에서 막히는 분들을 위해 만들었습니다. 화면과 AI 안내는 6개 언어(한국어·English·中文·Tiếng Việt·日本語·ไทย)를 지원합니다.

## 접속 주소

| 구분 | 주소 |
| --- | --- |
| 서비스 | **https://document-assistant-main.onrender.com/assist** |
| 홍보영상 | https://document-assistant-main.onrender.com/promo |

- 별도 가입 없이 휴대폰·PC 브라우저에서 바로 사용할 수 있습니다. 휴대폰 화면에 맞춰 설계했습니다.
- 처음 화면의 **먼저 예시로 살펴보기**를 누르면 예시 서류(전기안전공사 정기검사 신청서)로 전체 흐름을 바로 체험할 수 있습니다.
- 공개 시험 서버라 사진 분석은 하루 100회, 같은 접속 주소(IP)당 시간당 10회로 제한합니다.

## 주요 기능

1. **사진 확인과 개인정보 가리기**
   카메라로 찍거나 저장된 사진을 고르면, 분석 전에 사진을 돌리거나 이미 적힌 개인정보 부분을 가릴 수 있습니다. 가린 부분은 AI에 보내지 않습니다.
2. **서류 이름 확인**
   AI가 먼저 서류 제목·발급 기관·용도를 읽어 "이 서류가 맞나요?"라고 확인합니다. 그동안 작성할 칸 찾기가 뒤에서 이어지고, 진행 상황(찾은 칸 수)을 실시간으로 보여 줍니다.
3. **작성할 칸 자동 인식**
   사진 위에 작성할 칸을 파란 상자로 표시합니다. 표 안의 칸도 셀 단위로 찾고, 칸 목록·확대 보기로 원하는 칸을 고를 수 있습니다. AI가 놓친 칸은 **빠진 칸 추가**로 직접 둘러 추가하고, 위치가 어긋난 칸은 고칠 수 있습니다.
4. **칸별 작성 안내**
   칸을 누르면 세 부분으로 나눠 안내합니다.
   - **설명**: 이 칸에 무엇을 적는지
   - **작성 예시**: 가상의 정보로 만든 예시
   - **확인 내용**: 다 쓴 뒤 스스로 점검할 항목(빠진 정보, 단위·형식, 다른 칸과 일치 여부 등)

   누구의 정보를 적어야 하는지처럼 상황에 따라 답이 달라지면 "본인 일인가요, 가족 일을 도우러 오셨나요?" 같은 쉬운 질문으로 먼저 확인합니다.
5. **공식 근거 찾기**
   서식 이름으로 공식 작성 안내·서식 자료를 검색해 안내에 반영하고, **안내의 근거**에서 어떤 자료를 참고했는지 보여 줍니다. 근거가 없으면 사진을 읽은 내용으로 설명했다고 밝힙니다.
6. **법령과 민원 절차**
   국가법령정보센터 Open API로 서식의 근거 법령·조문을 찾아 보여 주고, 접수처·준비물·수수료·처리기간 등 민원 절차와 현행 서식 원본 내려받기 링크를 안내합니다.
7. **6개 언어**
   처음 화면 위쪽 국기를 누르면 화면과 AI 안내가 그 언어로 바뀝니다. 서류에 인쇄된 항목명은 종이에서 찾을 수 있도록 한국어 원문을 함께 보여 주고, 법령·근거 자료는 한국어 원문 그대로 보여 줍니다.

## 사용 방법

1. **서류 사진 찍기**(또는 **찍어둔 사진 고르기**)를 누르거나, **먼저 예시로 살펴보기**를 누릅니다.
2. 사진 확인 화면에서 글자가 잘 보이는지 확인하고, 필요하면 돌리기·개인정보 가리기를 한 뒤 **사진으로 안내받기**를 누릅니다.
3. 서류 이름이 맞는지 확인합니다. 칸 인식이 끝나면 **네, 이 서류예요** 버튼이 켜집니다.
4. 사진에서 궁금한 파란 칸을 누르거나 **칸 고르기**에서 칸을 고릅니다.
5. 설명 → 작성 예시 → 확인 내용을 넘겨 보며 **종이에 직접** 적습니다. **다음 칸 보기**로 다음 칸으로 넘어갑니다.
6. 필요하면 **안내의 근거**, **법령과 민원 절차**를 열어 참고 자료를 확인합니다.

> 이 서비스는 서류 작성을 대신하지 않습니다. 실제 개인정보는 앱에 입력하지 말고 종이에 직접 적어 주세요. AI 안내는 참고용이며, 최종 내용은 서류를 받는 기관의 기준을 따릅니다.

## 작동 방식

```
사진 (브라우저에서 축소·회전·가리기)
  → /api/documents/analyze  (스트리밍 응답)
      1. 서류 이름·용도 빠르게 확인        → 화면에 "이 서류가 맞나요?"
      2. 작성할 칸 찾기 (표 셀 탐지 + AI 판독, 찾는 대로 순차 전달)
      3. 공식 서식·작성 안내 웹 검색
      4. 근거 법령·민원 절차 조회 (국가법령정보센터 Open API)
  → /api/documents/guide    칸을 누를 때마다 그 칸의 설명·예시·확인 내용 생성
```

- **AI**: OpenAI Responses API(구조화 출력, 웹 검색)를 서버에서만 호출합니다. 브라우저에는 API 키가 전달되지 않습니다.
- **법령**: 국가법령정보센터 Open API로 법령·행정규칙 정본을 조회하고, 결과는 서버에 캐시합니다.
- **저장**: 별도 데이터베이스 없이 분석 결과를 서버 메모리에 30분만 보관합니다. 사진과 결과를 영구 저장하지 않습니다.
- **화면**: Next.js 16(App Router)·React 19·TypeScript. 사진 축소·회전·가리기는 브라우저에서 처리해 서버에는 가린 뒤의 사진만 보냅니다.

## 직접 실행하기

### 준비물

- Node.js **24.x**와 npm
- OpenAI API 키(사용할 모델 권한 포함)
- 국가법령정보센터 Open API 인증값(OC). 없으면 법령·민원 절차 기능만 동작하지 않습니다.

### 설치와 실행

```bash
git clone https://github.com/jinnie99/document-assistant.git
cd document-assistant
npm ci
cp .env.example .env.local   # 아래 환경 변수를 채웁니다
npm run build
npm run start -- --port 3000
```

브라우저에서 http://localhost:3000/assist 를 엽니다(`/`도 이 화면으로 이동합니다).
코드를 고치면서 실행하려면 `npm run dev`를 사용합니다.

### 환경 변수 (`.env.local`)

| 이름 | 필수 | 설명 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 예 | 서류 판독·검색·안내에 쓰는 OpenAI 키(서버 전용) |
| `OPENAI_MODEL` | 아니요 | 사용할 모델. 비우면 기본 모델을 씁니다. |
| `LAW_OPEN_API_OC` | 권장 | 국가법령정보센터 Open API 인증값(서버 전용) |
| `ANALYSIS_DAILY_LIMIT` | 아니요 | 하루 전체 사진 분석 횟수 제한. 비우면 제한 없음 |
| `ANALYSIS_HOURLY_LIMIT_PER_IP` | 아니요 | 접속 주소(IP)당 시간당 분석 횟수 제한. 비우면 제한 없음 |

키 값은 저장소에 올리지 않습니다(`.env.local`은 git에서 제외됨).

### 배포 (Render)

저장소의 `render.yaml`로 Render Web Service(Node 24)를 만들 수 있습니다. 빌드 명령은 `npm ci --include=dev && npm run build`, 실행 명령은 `npm run start -- --hostname 0.0.0.0 --port $PORT`이며, `OPENAI_API_KEY`·`LAW_OPEN_API_OC`는 Render 화면에서 직접 입력합니다.
분석 한 번이 1분 이상 걸릴 수 있고 분석 결과를 서버 메모리에 두기 때문에, 요청 시간이 짧은 서버리스 환경보다 계속 실행되는 서버에서 운영합니다.

## 코드 검사

```bash
npm test                                   # 단위·회귀 테스트
npx tsc --noEmit                           # 타입 검사
npx eslint app components lib scripts tests
npm run build
```

`npm run lint`는 함께 배포하는 PDF.js 작업자 파일까지 검사하므로, 앱 소스는 위처럼 범위를 지정해 검사합니다.
테스트 통과가 AI가 모든 서류의 칸을 정확히 인식한다는 뜻은 아닙니다. 알려진 한계는 `docs/KNOWN_ISSUES.md`에 정리했습니다.

## 폴더 구성

| 경로 | 내용 |
| --- | --- |
| `app/assist/`, `components/document-assistant/` | 서비스 화면(사진 확인, 분석 진행, 칸 선택, 칸별 안내, 대화상자) |
| `components/document-assistant/messages/` | 6개 언어 화면 문구 |
| `app/api/documents/` | 분석 스트림, 칸별 안내, 칸 추가·수정, 번역, 법령 API |
| `lib/documents/` | OpenAI 연동, 칸 탐지·좌표 계산, 검색 근거 처리, 검증, 메모리 저장소 |
| `lib/legal/` | 국가법령정보센터 API, 법령 후보 판별, 캐시, 절차 근거 처리 |
| `lib/i18n/` | 언어 목록과 언어별 안내 길이 기준 |
| `tests/` | 단위·회귀 테스트와 가상 서류 이미지 |
| `docs/` | 사용 매뉴얼(PDF·DOCX), 알려진 한계, 검증 결과 |
| `submit/` | 출품용 홍보영상(`/promo`에서 재생) |
| `public/samples/` | 예시 서류 사진 |
| `app/try/`, `app/legacy/` | 이전 실험 화면(참고용, 주 서비스 아님) |

글꼴과 PDF.js의 라이선스는 `third-party/`에 있습니다.
